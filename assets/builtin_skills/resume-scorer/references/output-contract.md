# 默认输出契约

本文件规定 resume-scorer-skill 的默认输出结构与字段顺序。示例与 prompts 输出须对齐本契约，除非用户明确要求其他格式。

---

## 默认输出顺序

### 1. 一句话总评

用一句话概括整体质量或筛选结论（如「结构完整但量化不足，与 JD 中等匹配」）。

### 2. 总分

给出 0–100 总分。

有 JD 时（`resume+jd` / `project+jd`）须额外附 **岗位匹配度（fit score）**，0–100。

### 3. 分项评分

逐维输出：**维度名 + 分数 + 简短理由**。

维度名须与 `references/rubric.md` 及对应 `prompts/scorer_*.md` 一致：

- resume：完整度、影响力、清晰度、针对性、可信度
- project：背景上下文、个人主导度、技术深度、影响力、清晰度
- jd：岗位清晰度、要求具体度、结构完整度、吸引力、筛选效率

### 4. 主要优势 / 主要问题

各 2–4 条，须可追溯到原文，不编造事实。

### 5. 优先修改建议

3–5 条，按优先级排序，表述具体、可执行。

### 6. 可选扩展

以下字段按场景与用户请求输出，不强制全部出现：

| 字段 | 触发条件 |
| --- | --- |
| 匹配关键词 / 缺失关键词 | 输入含 JD 时 |
| 改写稿 | 用户要求改写时 |
| 导出 `{stem}.scored.md` | 用户要求保存评分结果时 |
| 导出 `{stem}.rewritten.md` | 用户要求保存改写稿时 |

`{stem}` 为输入文件主文件名（不含扩展名）；若无文件输入，可用用户指定的输出前缀。

---

## 占位符格式

改写或补全信息时，对原文未提供且不应编造的内容使用：

```text
[待补充：具体说明缺什么]
```

示例：`[待补充：上线后的 QPS 或响应时间]`、`[待补充：团队规模与个人职责边界]`。

禁止用虚构数字或经历填充占位符位置。

---

## 与受众模式的关系

输出顺序与字段不变；求职者模式侧重修改建议的可执行性，招聘方模式侧重筛选结论与缺口清单。详见 `references/rubric.md` 用法说明。
