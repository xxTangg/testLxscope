# 招聘方快速筛选示例

> **说明：** 以下分数与文案为示意输出，非固定标准答案。结构对齐 `references/output-contract.md`。

---

## 输入：候选人摘要

```markdown
**候选人：** 陈磊 · 后端开发 · 4 年经验

**最近经历（2021.03–至今）**
- 某金融科技公司，Java 后端，参与交易与清算相关服务
- 使用 Spring Boot、MySQL、Redis；负责接口开发与日常运维支持
- 简历未写团队规模、未写具体 QPS/延迟指标，未提及消息队列或分布式事务

**教育：** 本科 · 计算机相关专业
```

---

## 输入：岗位 JD（节选）

```markdown
## 资深 Java 后端工程师（支付核心）

**要求摘要**
- 5+ 年 Java 后端，熟悉高并发、分布式与消息队列（Kafka/RocketMQ）
- 有支付、清结算或账务核心系统经验，能独立负责模块设计与稳定性治理
- 熟悉 MySQL 调优、缓存与限流降级方案
```

---

## 示意筛选输出

```text
一句话总评：行业方向部分相关，但年限、核心栈与支付深度未达 JD 硬性预期，建议待补材料后再定。

总分：61/100
岗位匹配度（fit score）：55/100

分项评分：
- 完整度：70/100 — 经历与教育有，缺项目分层与职责边界
- 影响力：52/100 — 几乎无量化，难以判断业务贡献
- 清晰度：72/100 — 可读，但信息密度偏低
- 针对性：48/100 — 金融科技相关，但未体现支付/清结算核心职责
- 可信度：58/100 — 工具栈可信，规模与结果证据不足

筛选结论：待补材料

主要优势：
- 有金融场景后端经验，Java + Spring Boot 栈匹配
- 工作年限接近区间下限，具备继续培养空间

缺口列表：
- 工作年限 4 年，低于 JD 要求的 5+ 年
- 未体现 Kafka/RocketMQ 等消息队列实践
- 未说明支付、清结算或账务核心的独立负责经历
- 缺少高并发、限流降级、稳定性治理相关描述
- 无量化指标（吞吐、延迟、故障恢复等），难以评估深度

建议下一步：
- 若业务急缺，可邮件索要 1–2 个清算/交易模块的技术说明或架构图
- 确认是否参与过核心链路而非外围接口；若无，当前阶段不建议推进至技术面
- 若候选人补充 MQ 与稳定性案例且可验证，可重新评估 fit score
```
