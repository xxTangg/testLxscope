# Excel ↔ Word 联动工具 · 需求与设计文档

> 本文件用于「下次无损恢复上下文」——只读这一篇，就能完整理解这个工具是什么、为什么这么做、怎么用。
> 最后更新：2026-06-02

---

## 1. 一句话说明

把 Excel 里的数据填进 Word 文档，实现 Excel↔Word 联动。Excel 数据改了，重跑一次就出新 Word。
底层是脚本驱动（python-docx + openpyxl），**不是** Office 原生"粘贴链接"——好处是能算账、能保留格式、跨平台。

---

## 2. 需求背景（要解决什么问题）

- **场景**：财务报表附注、各类正式报表——一份格式固定的 Word + 一份数据 Excel，每期（每月/每季）要根据新数据重新出一份 Word。
- **痛点**：手工把 Excel 几十上百个数字一个个抄进 Word，慢且易错；尤其涉及合计、占比、同比这些**算出来的**数字。
- **关键约束**：
  1. **普适**——不绑死某一份文档，任意 Word + Excel 都能处理。
  2. **大部分模板固定**——每期只换数据，希望复用、秒出。
  3. **偶尔人为微调**——模板可能被人改文字/挪表格，要能灵活适配。
  4. **调整主要用 Claude**——通过对话告诉 Claude 怎么改，而不是自己写代码/改文件。
  5. 要能**算账**（合计/毛利率/同比/会计括号负数）。

---

## 3. 核心使用场景（日常怎么用）

**把一个 Word 和一个 Excel 发给 Claude**，Claude 走五步：

```
你发我 Word + Excel
   ↓
① 探查    我跑脚本看清两个文件的结构（Word 每段/每格带坐标，Excel 每个 sheet）
   ↓
② 自动识别  我推断「Word 哪个位置 ← Excel 哪个值」，生成对应关系草案表
   ↓
③ 人工检查  草案列给你，我把没把握的标出来问
   ↓
④ Claude 调整  你说「第3条改成取税款、第5处不动」，我改
   ↓
⑤ 填充     按确认后的清单出成品，再做残留+对账校验
```

**你只在我的草案上改几处**，不用从头描述、不用碰 Word。

## 4. 方案演进（为什么是现在这样）

### v1：占位符 + 双击（已降级为"离线模式"保留）
- 做法：Word 里写 `{{占位符}}`，Excel 三列「占位符名 | 值 | 格式」，双击 `.bat`/`.command` 整本替换。
- 问题：① 必须**先把正式 Word 挖成占位符模板**，破坏原件、门槛高；② 占位符名要人手维护；③ 模板改了占位符对不上会**静默漏填**。
- 保留场景：要发给同事在他自己电脑上**双击运行、不经过 Claude** 时仍可用。入口 `scripts/fill_word.py` + 根目录 `数据.xlsx`/`模板.docx`/`一键更新-*.bat/command`。

### v2：自动识别 + 可复用 mapping（当前主线）
- 做法：探查 → 我识别 → 你对话调整 → 存 `mapping.json` → 填充。
- 比 v1 好在：① **不用改原 Word**（按现有文本/坐标定位）；② **我自动识别**，不用人手建映射；③ `mapping.json` **可复用**，换数据不用改；④ 模板微调有 **`--check` 检测**主动标差异。

### 为什么不换 docxtpl / Office 邮件合并
- **docxtpl（Jinja 模板）**：模板能力更强（行循环/条件），但**必须先把 Word 改成带标签的模板**——和"不破坏原文档"冲突。当前 find/cell 定位不用动原件，更贴合需求。
- **Office 粘贴链接 / 邮件合并**：算不了派生值（合计/同比只能搬原值），且链接易断、跨机器失效。要算账就出局。

## 5. 工作流详解（三种状态）

### A. 首次，或模板被改了 → 重新识别建 mapping
```bash
python3 scripts/inspect_files.py word.docx data.xlsx     # 探查，我读结构
# 我识别 → 你对话调整 → 我写出 mapping.json
python3 scripts/apply_mapping.py mapping.json word.docx 输出.docx --excel data.xlsx
```

### B. 每期（模板没变，只换数据）→ 复用 mapping，秒出
```bash
python3 scripts/apply_mapping.py mapping.json word.docx 输出.docx --excel 新数据.xlsx
```
因为 mapping 里用 `source` 指向 Excel 来源（不写死值），换数据自动出新值，**零识别、零人工检查**。

### C. 模板被人微调了 → 先检测，只补差异
```bash
python3 scripts/apply_mapping.py mapping.json 微调后.docx --check --excel data.xlsx
```
`--check` 只检测不写，逐条报告哪几条「对不上了」（坐标越界/找不到原文/取值失败）。
你只针对报错那几条，用对话告诉我怎么调，我更新 mapping，再填充。

## 8. mapping.json 是什么（核心资产）

它是「这份文档的对应关系记忆」，可复用、可版本化。每条说明「往哪填、填什么、怎么格式化」：

```json
[
  {"locate": {"type": "cell", "table": 0, "row": 1, "col": 1},
   "source": {"sheet": "明细", "key": "货款"}, "format": "money", "note": "表0货款"},
  {"locate": {"type": "find", "old": "0.00", "para": 3},
   "source": {"sheet": "基本信息", "key": "应付金额"}, "format": "money", "note": "P3 金额"}
]
```

- **locate（往哪填）**：`cell` 表格坐标 / `find` 正文查找 / `placeholder` 占位符。
- **取值**：`source` 从 Excel 现取（推荐，换数据不用改）/ `value` 写死常量。
- **format**：`money` / `pct` / `int` / `text` / 留空自动。

完整字段说明见 `references/映射清单格式.md`。

## 9. 已知限制（如实记录）

- **不自动刷新**：Excel 改完要主动跑一次，Word 不会自己变。
- **跨 run 的段内混合格式可能丢**：python-docx 把文本切成多 run，要替换的文字若跨 run 会合并到首 run（脚本会报告哪几条发生合并，需目检）。单 run 内格式（如整个数字加粗）能完整保留。
- **重复文本定位**：`find` 默认取全文首个匹配，原文多处重复时要加 `para`/`cell` 精确定位。
- **派生值取不了**：合计/占比/同比这类要算的，`source` 取不了，得在 Excel 先用公式算好，或走进阶范例的计算脚本。
- **依赖**：需 Python 3 + `openpyxl` + `python-docx`。
