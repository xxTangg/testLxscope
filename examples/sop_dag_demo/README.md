# 本地 SOP DAG 演示

三套 SOP 使用虚构业务数据和确定性的本地模拟模型，实际经过正常的会话、工具提交、DAG 调度、审核和状态持久化流程。模拟器不会直接写入运行状态，也不会调用真实大模型或外部业务接口。

## 启动与预置

在项目根目录运行：

```sh
docker compose -f docker-compose.yml -f docker-compose.sop-demo.yml up -d --no-deps sop-demo-model
python3 examples/sop_dag_demo/seed.py --username test --start
```

脚本会提示输入该账号的现有密码，不会修改密码。预置使用正常登录后的 API，仅添加演示凭证、两名演示智能体及三套 SOP；按名称和运行标记避免重复添加，不改动其他资源。容器只连接当前 Compose 内部网络，没有发布宿主机端口。重启 Docker 后会自动重启模拟器。

## 体验顺序

使用 `test` 账号打开 <http://127.0.0.1:13001/sop>。

1. **新品发布方案**：需求拆解 → 用户画像、渠道创意、预算测算三路并行 → 汇总。预置一份完成记录；点击「启动运行」可以实时观察，每个并行分支模拟耗时约 7–11 秒。
2. **电商经营复盘**：准备数据 → 销售、库存两路并行 → 人工审核 → 行动清单。预置记录停在人工审核，点击「通过」后观察下游继续运行。
3. **数据日报**：准备数据 → 质量校验、指标计算并行 → 日报。质量校验首次故意失败，汇总被阻塞。预置两份记录：一份失败等待你手动点击「只重试此节点」，一份已执行局部恢复。后者的尝试历史应为：准备 1 次、质量校验 2 次、指标 1 次、汇总 1 次。

每个节点的结构化输出包含 `received_inputs`，可以核对真实的上游输入映射。日报最终收入根据修复后的数据重算，不会把旧指标冒充为修复后的结果。

演示模型仅支持内置场景，不能执行任意自然语言任务。使用真实任务时，编辑 SOP 的节点模型和演示描述，替换为你的模型凭证。演示不会产生真实模型调用费用。
