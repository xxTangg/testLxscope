# 使用真实 DeepSeek 的轻办公 SOP

三套任务：产品周会纪要、客户反馈周报、半天培训筹备。业务原始材料是虚构的练习素材；所有分析、结构化交接、最终文档及审核决定均由账号自己的 DeepSeek 模型实际生成。没有模拟端点、预置答案、故意失败指令或直接修改运行状态。

```sh
python3 examples/sop_office/run.py --username test --start
```

输入账号密码后，脚本选择该账号唯一的 `deepseek_credential`。有多份凭证时用 `--credential-id` 指定；默认模型 `deepseek-v4-flash`，可用 `--model` 指定系统中可用的其他 DeepSeek 模型。真实调用会消耗该凭证的模型额度。

每套任务都是“资料整理 → 两个独立分析分支 → 文档汇总”，最终文档由独立会话审核；实质性错误会触发正常的自动重试，尝试上限为两次。没有错误时可以一次完成。

默认权限模式保持 `default`。节点主要使用 `SubmitHandover` / `SubmitVerdict`；模型也可能根据环境提示主动请求本地计算或临时文稿工具，此时在节点会话中按次核对并处理工具授权，脚本继续等待。任务不要求外网检索、发送消息或修改外部系统。最终文档保存在节点的 `data.report_markdown` 输出中；脚本通过正常 API 导出运行记录与 Markdown 到 `outputs/sop_office/<运行 ID>/`。

脚本按 SOP 名称与运行标记避免重复创建，旧的本地模拟示例继续保留。每次手动点击「启动运行」会调用 SOP 里配置的真实模型；可以把新业务材料粘贴到启动输入框。
